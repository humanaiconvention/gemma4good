## Why H20 passed where H19 failed

H19 and H20 used the same Unicode normalization function. The two
hypotheses differ in scope:

| | H19 (FAILED) | H20 (PASS) |
|---|---|---|
| Unicode normalization (the L-01 fix) | yes | yes |
| Multi-message scan | yes (the L-02 attempt) | no (deferred to H21) |
| System-role-in-history rejection | yes | no (deferred to H21) |
| Predicate count | 16 gates | 14 gates |
| Result | FAIL on D1 (0.80 < 0.95) and D2 (0.80 < 1.00) | PASS on all 14 |

H19's failure was diagnosed in [`docs/h19_verdict_2026-05-16.md`](h19_verdict_2026-05-16.md)
as a **suite design flaw**, not a normalization failure. The
multi-message attack suite conflated multi-message iteration logic
(the actual H19-D claim) with v1 rule-coverage gaps (an orthogonal
property). H20 isolates the Unicode mitigation as one variable with
clean predicates and demonstrates it works.

The H19 multi-message claim has NOT been refuted by H20 — only
deferred to a future H21 with a properly-scoped multi-message suite
where every attack prompt is also an H18-rule-matching single-message
attack. H21 is not yet predeclared.
