## What H22 changed in guard-v5

A single behavioral change vs guard-v4:

- **Added:** A `_detect_system_role_injection(body)` check at the
  start of `chat_completions`. If any non-first `messages[i]` has
  `role: "system"` (i.e. `i > 0`), the request is rejected with HTTP
  400 and structured detail `system_role_in_history: only the first
  message may be role:system`.

- **Unchanged:** The 16-rule set, Unicode normalization, per-message
  user scan, deterministic refusal phrasing, audit log contract,
  pass-through allowlist, lifespan management, error handling.

This is the same logic that lived in guard-v2 (H19's failed
candidate), now isolated under a correct predeclaration that
explicitly distinguishes the operator's position-0 system prompt
(passed through) from client-supplied position-N (rejected).
